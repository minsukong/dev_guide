# 백엔드 AI 개발 가이드

라운지 3.0 백엔드 개발팀에 공유하기 위한 **개발자와 AI의 협업 가이드**입니다. 라운지 프로젝트의 docs를 바탕으로, 요구 확인부터 설계·구현·테스트·리뷰·인수인계까지 AI와 함께 진행하는 방법을 정리했습니다.

개발자는 작업의 목표·범위와 필요한 결정을 맡고, AI는 자료·코드 조사, 설계안 작성, 구현과 검증을 지원합니다. 기획 자료·현재 코드·공유된 결정을 함께 확인하고, 실제 테스트 결과를 기준으로 작업을 이어가는 것이 핵심입니다.

## 먼저 읽을 문서

**[백엔드 AI 개발 가이드 — index.html](index.html)**을 브라우저에서 열면 전체 흐름과 사용 예시를 볼 수 있습니다. 폴더를 내려받아 `index.html`을 열어도 됩니다.

| --- | --- |
| [index.html](index.html) | 사람용 안내: 협업 흐름, 시작 예시, AI 도구·자료 연결 방법 |
| [AGENTS.md](AGENTS.md) | AI가 작업을 시작할 때 읽을 공통 지침과 스킬 선택 기준 |
| [workflow/README.md](workflow/README.md) | 작업 순서, 완료 기준, 공유 기록과 가이드 운영 방법 |
| [workflow/development.md](workflow/development.md) | 기획 자료·도메인·API·데이터·보안·테스트 확인 기준 |

## 시작하기

1. `index.html`에서 협업 흐름과 시작 예시를 확인합니다.
2. AI에게 이 가이드의 `AGENTS.md` 경로, 실제 백엔드 저장소, 기획 자료와 프로젝트의 공유 기록 위치를 전달합니다.
3. 이번에 진행할 기능과 요청 범위가 기획 검토·설계·구현·리뷰 중 어디까지인지 지정합니다.
4. 작은 실제 작업으로 자료 읽기, 코드 확인, 검사 실행, 결과 기록이 연결되는지 확인합니다.

AI에 전달할 첫 요청은 아래처럼 작성할 수 있습니다. `<...>` 부분은 실제 경로와 작업 내용으로 바꿉니다.

```text
AI 협업 가이드: <이 폴더의 AGENTS.md 경로>
백엔드 저장소: <소스 경로>
기획 자료: <PPT 파일 또는 Figma 링크와 검토 범위>
프로젝트 문서: <docs 목차 등 기존 문서 진입점 / 없다면 없음>
공유 기록: <팀의 결정·작업 기록 위치 / 미정이면 미정>

작업: <대상 기능과 요청 범위>

가이드의 AGENTS.md를 읽고 이번 작업에 필요한 스킬을 적용해줘.
관련 기획·코드·공유 결정을 확인하고, 확인한 사실과 미정 사항을 구분해줘.
구현 작업이면 필요한 검사를 실행하고 실제 결과와 남은 검증을 기록해줘.
```

가이드를 소스 저장소 밖에 두는 경우에는 AI가 자동으로 읽는다고 가정하지 않습니다. 새 대화나 작업 재개 시에도 가이드와 대상 저장소·공유 기록 위치를 전달합니다. 별도 스킬 자동 등록이나 외부 번들 설치 없이, 이 폴더의 지침과 필요한 `SKILL.md`를 읽는 방식으로 시작할 수 있습니다.

## 적용과 운영

이 자료는 라운지 docs를 바탕으로 정리한 협업 절차입니다. 실제 언어·프레임워크·DB, 빌드·테스트 명령과 개발표준은 백엔드 팀의 저장소와 실행 환경에 맞춰 적용합니다. 업무 정책과 API 계약은 해당 프로젝트의 승인된 자료·공유 결정을 확인하고, 미정 사항은 담당과 영향 범위를 기록해 확인합니다.

팀의 결정·설계·작업 결과는 기존에 사용하는 공유 위치에 남깁니다. 이 폴더의 기록 양식은 참고해 사용하되, 개인 복사본마다 팀의 결정을 따로 관리하지 않습니다. 가이드를 복사해 사용할 때는 원본 위치와 기준 버전 또는 배포일을 함께 남깁니다.

완료 여부는 실제 빌드·정적검사·테스트 결과와 리뷰를 근거로 판단합니다. 실행하지 못한 검사와 남은 정책·연동 확인은 구분해 기록하고, 사용 중 드러난 문제는 공통 지침과 스킬에 반영합니다.
