# 백엔드 Workflow

개발자와 AI가 요구 확인부터 설계·구현·테스트·리뷰까지 함께 진행하는 공통 개발 프로세스다. 개발자는 목표·범위와 필요한 결정을 맡고 AI는 조사·설계안·코드·테스트·기록을 지원한다. PPT·Figma 등 기획 자료와 실제 코드·공유 결정을 근거로 작업한다. 스킬 선택은 [루트 지침](../AGENTS.md), 설계·검증 항목은 [개발 기준](development.md)을 본다.

## 테스트 결과를 기준으로 협업하기

반복 확인은 프로젝트의 공통 빌드·정적검사·테스트로 묶고 개발자와 AI가 같은 명령과 결과를 사용한다. 공통 검사 구성과 실행 환경은 백엔드 팀이 개발표준과 실제 저장소에 맞춰 관리한다. 새 도구의 세부 설정은 이 가이드에서 일괄 지정하지 않는다.

작업 시작 시 기존 검사 결과를 확인하고, 변경할 때 관련 테스트를 작성·수정해 필요한 검사를 실행한다. 실패는 AI와 원인을 조사해 수정·재실행한다. 개발자는 중요한 업무 판단과 자동화하지 못한 범위를 확인하고, 리뷰에는 실제 결과와 남은 검증을 남긴다. AI의 완료 보고만으로 통과를 판단하지 않는다. [전체 협업 흐름](../index.html#purpose)을 참고한다.

## 처음 연결할 때

AI가 소스·기획 자료를 읽고 테스트를 실행하려면 각 자료 형식과 작업에 맞는 파일 접근·실행 도구가 필요하다. 공용 스킬은 작업 지침이고, MCP는 외부 자료·기능을 AI 도구에 연결하는 방식이다. 이 연결과 실행 설정은 각자의 하네스에서 구성한다.

작은 자료 범위로 실제 읽기를 확인한다. PPT는 [파일·슬라이드 읽기 기준](development.md#ppt-input), Figma(기획서)는 [연결·접근 기준](development.md#figma-access)을 적용한다. 반복해서 쓸 규칙·계약·실행 방법이 쌓이면 [프로젝트 docs로 정리해 운영하는 방식](project-docs.md)을 권장한다. 공용 가이드와 프로젝트 지식을 연결해 다음 AI 작업에서도 재사용한다. 시작 순서는 [HTML 도입부](../index.html#purpose)를 따른다.

## 작업 흐름

| 단계 | 확인할 내용 | 결과 |
| --- | --- | --- |
| 기획 검토 | 제공된 기획 자료·확인 가능한 정책·코드에서 확인한 규칙과 미정 | 결정 질문·담당·영향 |
| 설계·작업 계획 | 도메인·API·데이터와 소비자 영향, 실제 선행 조건 | 설계·작업 범위·완료 조건 |
| 구현·검증 | 범위에 필요한 조건과 정상·실패·경합 동작 | 변경 코드·테스트 근거 |
| 리뷰 | 요구 충족·결함·호환성·미검증 범위 | 수정 항목·다음 작업 |

단계마다 별도 문서를 만들 필요는 없다. 작은 변경은 필요한 스킬만 사용하고 결과를 짧게 기록한다. 여러 작업에 걸친 기능만 프로젝트의 공유 설계 기록에 설계·계획을 정리하고 실제 작업 카드와 연결한다. 팀이 이 폴더를 기록 위치로 정했다면 tasks/SPEC-기능.md를 사용할 수 있다.

## 프로젝트 docs를 함께 운영하는 권장 확장

처음에는 기획·소스·작업과 결정 기록으로 시작한다. 기능과 참여자가 늘면 반복해서 참조하는 내용을 프로젝트 문서로 정리하고, 문서 목차에서 이번 작업의 정책·API·데이터·실행 안내를 선택하게 한다. 설계·구현·검증 후 바뀐 문서도 갱신해 다음 개발자·AI 작업으로 이어간다.

공용 가이드에 프로젝트 지식을 복제하거나 모든 문서를 매번 읽게 하지 않는다. 기존 API 명세·공유 문서는 기준 위치를 유지한다. [운영 예시와 AI 요청 방법](project-docs.md), [설명·다이어그램](../index.html#project-docs)을 참고한다.

## 미정 정책과 진행 범위

PPT의 관련 슬라이드·설명, Figma(기획서)의 화면·주석 등 제공된 자료와 관련 결정을 먼저 확인한다. 파일·버전·슬라이드 또는 링크·노드, 확인 날짜·관찰 범위를 남기고 확인한 내용과 미확인·충돌·접근 불가를 구분한다.

업무상 허용 행위·권한·취소·만료 규칙은 기획·운영과, 요청·응답·이벤트·오류 의미는 소비자·연동 담당과 확인한다. 합의된 규칙을 만족하는 모델·트랜잭션·동시성 제어 등 기술 설계는 백엔드 개발자가 판단한다.

기획서 보완이 필요한 미정은 결정 기록에 남긴다. Figma(기획서)에 코멘트를 남기는 경우 [공통 코멘트 양식](decisions.md#comment-template)을 사용한다. 사람이 직접 작성하거나 AI에게 초안·게시를 요청할 수 있다. 게시 지원·권한을 확인하고 실제 결과를 구분한다. 질문·담당·영향받는 작업·재개 조건과 코멘트 링크는 프로젝트의 같은 공유 결정 항목에 연결한다. 이 폴더의 decisions.md는 양식과 후속 기록 기준을 참고하는 위치다. 설계와 구현에서 이번 범위에 필요한 정책·계약·데이터 조건을 확인한다.

독립된 조회 요구가 확인되면 조회 작업을 먼저 진행할 수 있다. 반면 상태 전이 자체가 미정이면 변경 API와 저장 모델도 영향을 받을 수 있으므로 구현을 자동 분리하지 않는다. API·스키마 제안과 합의된 사양, 테스트 대체물과 실제 연동을 구분한다.

## 완료와 인수인계

API 계약·변경 영향은 설계와 리뷰에서 확인한다. 단위·DB 통합·API 계약·외부 연동 테스트는 변경 영향에 따라 선택하고, 실제 저장소의 명령으로 실행한다. 모든 기능에 모든 검증을 강제하지 않는다.

진행 상태는 Todo / In Progress / Review / Done / Blocked로 남긴다. 필수 완료 조건이 실패하거나 미검증이면 Done으로 처리하지 않는다.

[작업 기록](task-template.md)에 변경 파일·스키마·계약, 검증 대상·환경·명령·결과(Pass / Fail / Not Run / N/A), 남은 정책·연동·운영 확인과 다음 담당을 남긴다. 카드 범위의 완료와 서비스·배포 완료를 구분한다. 여러 작업에 걸친 변경이나 인수인계에는 비교 기준 브랜치·커밋과 검증한 코드 상태, 결과 커밋·PR 링크를 해당할 때 남긴다. 미커밋 변경은 포함 범위와 diff·패치 위치 등 다시 확인할 근거를 남기며, 기록을 위해 commit·push를 강제하지 않는다. 검증·리뷰 뒤 코드가 바뀌면 영향받는 검증·리뷰를 갱신하고 이전 결과를 그대로 완료 근거로 쓰지 않는다.

## 공유 기록 위치와 가이드 갱신

개인별 AI 도구·연결은 달라도 같은 프로젝트의 결정·작업 기록은 함께 확인할 수 있어야 한다. 처음 연결할 때 프로젝트 담당과 다음 위치를 정하고, 작업 요청이나 기존 저장소 안내에 경로·링크를 남긴다. 이미 정해진 위치가 있으면 재사용한다.

- 공용 가이드 원본·관리 담당과 사용할 버전 또는 커밋. 버전 관리가 없으면 배포일·변경 내역으로 구분한다.
- 프로젝트의 결정 기록, 작업·설계 기록, 합의된 API 계약을 공유할 기준 위치. 저장소·공유 문서·이슈 도구 등 팀이 쓰는 위치를 선택하며 새 도구를 만들 필요는 없다.
- 이 폴더의 `decisions.md`와 `task-template.md`는 기록 구조와 양식이다. 팀이 이 폴더를 공유 기록 위치로 정했다면 사용할 수 있지만, 개인 복사본마다 실제 결정을 따로 관리하지 않는다. 질문·결정 ID와 작업 링크는 프로젝트의 공유 기록에 연결한다.
- 복사해서 쓰는 가이드는 원본 위치·기준 버전을 남긴다. 새 작업을 시작하거나 중단된 작업을 재개할 때 원본의 변경 여부와 관련 결정·계약이 대체됐는지 확인한다. 갱신할 때 개인 연결 설정과 프로젝트 기록을 덮어쓰지 않는다. 원본을 확인할 수 없으면 사용한 버전과 미확인 범위를 남긴다.

공유 위치가 아직 없다면 담당과 위치를 정할 질문을 남기고 조사·설계 등 독립 작업을 진행한다. 개인 메모는 공유 기록에 반영하기 전까지 팀의 확정 기준으로 취급하지 않는다. 다른 프로젝트에 이 가이드를 적용할 때는 그 프로젝트의 기록 위치를 연결한다.

## 개인 하네스

각자 AI 도구에 PPT 등 파일·Figma(기획서) 읽기, 코드 검색, 빌드·테스트 실행을 연결한다. 공용 원본을 직접 읽는 방식으로 시작할 수 있으며, 자동 발견·호출 설정은 개인 환경에서 구성한다. 복사해서 사용하면 폴더 구조와 상대 경로를 유지한다. 소스 저장소 밖의 가이드는 자동 적용을 전제하지 않고, 첫 요청과 새 대화·작업 재개 시 가이드의 AGENTS.md·저장소·공유 기록 경로를 전달한다. 자동 등록이 없어도 필요한 SKILL.md를 직접 읽어 적용할 수 있다. 작은 실제 작업으로 자료 확인부터 결과 기록까지 연결되는지 확인한다.

## 사용하면서 검증하고 보완하기

**이 가이드는 실행 지침이다. 연결·스킬 설정만으로 AI의 임의 판단이 자동 차단되거나 모든 누락이 발견된다고 보장하지 않는다.** 처음 연결할 때와 AI 도구·연결·지침을 바꾼 뒤에는 작은 실제 작업으로 확인하고, 사용 중 드러난 문제를 보완한다. 별도 대규모 검증 체계를 먼저 만들 필요는 없다.

- 실제로 적용한 AGENTS.md·SKILL.md와 읽은 자료·범위를 결과의 근거와 대조한다. 파일을 읽었다는 보고만으로 지침 준수를 판단하지 않는다.
- 불분명한 정책을 질문으로 남기는지, 문서 충돌·접근 실패를 구분하는지, 담당과 진행·보류 범위를 설명하는지 확인한다. 결정 기록이 다음 설계·구현에도 이어지는지 본다.
- AI가 정책·계약을 임의 확정하거나 근거 없는 경로·완료 결과를 만들면 영향받는 결과를 재검토하고 수정한다. 원인이 자료 연결·지침 누락·기록 단절 중 무엇인지 확인해 개인 하네스나 공통 스킬·문서를 해당 범위에서 보완한다.
- 같은 조건에서 필요한 범위를 다시 확인하고, 수행한 확인과 남은 미검증을 작업 결과에 남긴다. 하네스 동작 확인은 제품의 단위·DB·연동 검증을 대체하지 않는다.
