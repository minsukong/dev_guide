# TASK-기능-번호 — 작업 결과

프로젝트의 공유 작업 기록 위치에 복사해서 사용한다. 이 폴더를 팀의 기록 위치로 정했다면 tasks/를 사용한다. [공유 기록 기준](README.md#shared-records)을 따르고 작은 변경은 결과 보고에 통합한다. 코드 기준점·PR 항목은 여러 작업에 걸친 변경이나 인수인계에 해당할 때 작성하며, 기록을 위해 commit·push할 필요는 없다.

- 담당 / 저장소·서비스·모듈:
- 공유 작업 링크·관련 결정 ID / 적용한 가이드 버전·배포일: 해당할 때
- 비교 기준 브랜치·커밋 / 시작 시 포함한 미커밋 변경: 해당할 때
- 진행 상태: Todo / In Progress / Review / Done / Blocked

## 요구·범위·계획

- 목적·호출자·요구 근거: Figma(기획서)·정책·API·현재 코드
- 기획서 확인 범위·자료 날짜 / 직접 읽었다면 연결 방식·오류·미확인 범위:
- 포함 / 제외 / 완료 조건:
- 필요한 도메인·API·데이터 변경과 검증 계획:
- 실제 선행 작업·관련 명세:
- 미정·담당·영향 / 진행할 범위 / 보류 범위·재개 조건:
- 관련 기획서 코멘트 링크·ID / 초안·게시 상태: 해당할 때

## 결과·인수인계

- 변경 파일·스키마·계약 / 적용한 개발 기준:
- 검증·리뷰한 코드 상태 / 결과 커밋·PR 또는 diff·패치 위치: 해당할 때
- 검증·리뷰 이후 변경 / 영향받는 재검증·재리뷰 결과: 해당할 때
- 검증 대상·환경·명령·결과: Pass / Fail / Not Run / N/A
